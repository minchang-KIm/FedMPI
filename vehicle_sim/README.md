# 차량 연합학습 장애 시뮬레이터

차량 업데이트가 늦거나 오지 않는 34개 유스케이스(서버가 받은 모습 기준 8개 패턴)를 **실제 크기의 3D 도시에서 실제 FL 학습과 함께** 보여 주는 화면.
SASAFL 원본 파일(`methods/SASAFL/*`)은 수정하지 않고, `fl/sim_sasafl.py`의 서브클래스로 끼워 넣는다.

## 실행

```bash
# 이 폴더(~/Mando/FedMPI-sim, 브랜치 vehicle-fl-sim)에서, FL conda 환경의 python으로
/home/wise-175/anaconda3/envs/FL/bin/python vehicle_sim/serve.py --port 8765
# 브라우저: http://localhost:8765  (원격이면 VS Code 포트 포워딩으로 8765)
```

**▶ 시작**을 누르면 주행 시뮬레이터(world)와 FL(torchrun, 서버 1 + 차량 K)이 함께 뜬다. 3D 맵은 three.js를 인터넷에서 받는다.
34개를 한 번에 보려면 '전체 설정 → 34개 전부 보이기' 후 ▶ 시작, 몇 분 뒤 '서버 장애' 버튼(8-1·5-3).

## 맵 4종 (`maps/make_maps.py`로 생성)

| 맵 | 크기 | 특징 |
|---|---|---|
| `default` 도심 격자 | 2.0 × 1.4 km | 고속도로(100 km/h)·도심 순환로·교외 순환로, 300 m 터널, 빌딩 숲, 어린이 보호구역 |
| `highway` 고속도로 회랑 | 3.2 × 1.2 km | 두 도시 사이 산을 뚫은 1 km 터널(80 km/h ≈ 45초 단절), 톨게이트 권역 경계 |
| `port` 항만·산업단지 | 2.4 × 1.6 km | 지하차도, 컨테이너 야적장(음영), 해무(강우), 항만 게이트 혼잡 |
| `newtown` 신도시 순환 | 2.2 × 1.6 km | 외곽 순환대로·내부 순환로·방사형 도로, 업무지구 빌딩 숲, 학교·공원 |

모든 맵은 34개 유스케이스를 일으킬 조건을 갖춘다. 생성할 때 `common.map_coverage`(경로 위에 터널·음영·셀 가장자리·권역 경계·고속 구간·
충전소·서비스센터·집/직장 정차·Wi-Fi·강우·횡단보도가 있는지)와 `common.map_problems`(경로가 도로 위에 있는지, 정차 지점에 장소가 있는지,
3갈래 이상 교차로에 신호가 있는지)를 검사하고, 하나라도 빠지면 저장하지 않는다. 화면 '저장·맵' 탭에 맵별 34/34와 유스케이스별 위치가 나온다.
같은 형식의 JSON 맵을 올려도 같은 검사를 한다. 건물·나무·주차장 칸은 맵에서 자동 배치(`common.map_layout`, 맵 이름으로 시드 고정).

## 하루 시계 (7-3 운행 시간대 편중)

`world.day_minutes`(기본 30분 = 24시간), `world.start_hour`(기본 06:48). 화면 위쪽에 시각·일차·시간대(야간·출근·주간·퇴근·저녁), 하늘·해·조명·창문 불빛이 시각을 따른다.

| 차량 | 하루 |
|---|---|
| 통근 (commute) | 집에서 밤샘 주차 → 07:00–08:30 출근 → 직장 주차(시동 꺼짐) → 17:00–18:30 퇴근 → 귀가 |
| 택시 (city) | 주간조 06–24시 / 야간조 18–10시. 근무가 끝나면 차고지 주차, 가끔 휴식. 운행이 길어 학습 데이터 2배(4-6) |
| 주민 (resident) | 08–21시에 집에 들렀다 나가기를 반복, 밤에는 집 |
| 통과 (visitor) | 시간대별 유입(출퇴근 2.2배, 밤 0.15배) |

집에 주차하면 완속 충전, 충전소는 급속 충전. 보행자는 시간대별 빈도(학교 앞은 등하교 시간에 많음).
서버는 시간대별로 어떤 차량 종류의 값이 집계됐는지 기록하고(화면 '시간대별 참여'), 최근 W라운드 집계 구성이 차량 구성과 다르면 7-3을 기록한다.

## 주행 (강체: 차량끼리 겹치지 않음)

- 차량은 길이 4.6 m·폭 1.9 m 직사각형. 2차선 도로에서 진행 방향 오른쪽 차로 중심선을 따라가며, 모서리는 반경 9 m 곡선(곡선 구간 감속).
- 앞 경로를 1 m 간격으로 훑어 다른 차(앞차·교차로를 지나는 차, 방향 무관)를 찾아 그 앞에서 멈출 수 있는 속도로 줄인다.
- 매 0.1초 이동 후 차량 직사각형끼리 분리축 검사(SAT). 겹치게 되는 이동은 하지 않는다.
- 신호 교차로는 진입 예약: 다른 방향에서 들어온 차가 안에 있거나 출구가 막혀 있으면 정지선에서 기다린다 (교차로 안 교착 방지).
- 정차는 도로 밖 주차장 칸으로 들어가고, 차로가 비어 있을 때만 다시 합류한다.
- 검사: 4개 맵 × 차량 16대 × 3일(실제 90분)에서 겹침 0회, 가장 오래 선 시간 26초(빨간불).

## 학습 방식 (같은 하네스, 기능만 켜고 끔 → ablation)

| 방식 | 적응형 quota | staleness 감쇄 | 학습 중 교체·epoch 축소 | quota |
|---|---|---|---|---|
| SASAFL (현재 코드 + optimizer 수정) | O | O | O | C·K부터 |
| SASAFL 원저자 코드 | X | O | O | C·K |
| BSA (SemiAsync) | X | O | X | C·K |
| FedAsync | X | O | X | 1 |
| 동기식 | X | X | X | K |

시드가 같으면 데이터 분할·주행·차량별 무작위 사건이 같게 시작한다 (학습 시간에 따른 순서 차이는 남는다).

## 패턴을 만드는 방법

| 패턴 | 맵·설정 | 구현 / SASAFL이 보는 모습 |
|---|---|---|
| 1 값을 전달받지 못함 | 계산 중단, OTA, 학습 중 방전, 긴급제동 선점, 주차(시동 꺼짐) | 학습 중단, 보내지 않음. **프로세스는 살려 두고 수신은 계속**(원본은 한 대라도 수신을 멈추면 서버 `dist.send`가 막힌다) |
| 2 전송 중 끊김 | 범위 이탈·핸드오버, 도플러, 패킷 오류, 권역 경계, 터널, 전송 중 방전 | 전송 시간(업데이트 크기/대역폭)을 n등분해 기다리며 연결 확인, 끊기면 보내지 않음. 패킷 오류·도플러는 재전송으로 복구되면 4-3으로 이어짐. 실제 `dist.send`는 원본처럼 한 번 → 조각 개념이 없어 서버에선 패턴 1처럼 보인다 |
| 3 해당 라운드 미참여 | 에너지 기준, 새 데이터 없음(충전 중·정비 대기), Wi-Fi 조건 | 학습을 시작하지 않고, 조건이 풀리면 **마지막으로 받은 최신 글로벌 모델로 복귀** |
| 4 늦게 도착 | 구형 EV, 기지국 혼잡, 재전송, 대역폭·강우, 긴급제동 연산 점유, 데이터 양(택시), TDMA, 새 모델 수신 실패 | 지연 / 이전 버전으로 학습 → staleness |
| 5 모아서 한꺼번에 | 보관 후 전송 + 터널·음영·셀 가장자리, 서버 장애 | 보관했다가 연속 `dist.send`. 원본 서버는 차량당 버퍼 1칸이라 덮어쓰고 비중을 두 번 나눈다 |
| 6 오류 값 지속 전송 | 업데이트 증폭, 센서 고장 라벨, 학습률 | 매 업데이트마다 오염된 값 전송 (너무 세면 loss NaN → 서버 `int(NaN)` 종료) |
| 7 빠른 클라이언트 편중 | 신형/구형, 주행 중 통신 품질, 하루 시계 | 최근 W라운드 집계 구성을 감시: 신형 EV 비중(7-1), 통신 품질 상위 절반 비중(7-2), 시간대별 차량 종류 구성(7-3) |
| 8 서버·글로벌 모델 문제 | 서버 장애 버튼, quota > 보낼 수 있는 차량(밤), 새 모델 연속 거부 | 일시 중단 후 복구(차량은 보관), 무한 대기 감지, lag ≥ τ 강제 갱신 기록 |

## 원본과 다르게 둔 것
1. busy-wait 두 곳에 짧은 sleep (CPU 절약, 동작 동일)
2. **복귀 허용**(전체 설정): 원본은 한 번 빠진 차량이 다시 선택되지 않는다. 끄면 원본처럼 영구 제외
3. 학습 중 글로벌 모델 교체 뒤 optimizer를 다시 만든다 (main `8f430a7`의 버그 수정과 같음)

## 주의
- 실제 학습을 하므로 CPU를 쓴다 (차량 8대 ≈ 프로세스 9개, 1스레드씩). 같은 노드에서 다른 실험이 돌면 그 실험이 느려진다.
- 주행 시간·거리·속도는 실제 단위(1배)이고 하루 시계만 빠르게 간다 (기본 30분 = 24시간). 그래서 출퇴근 길이 시계로는 2–3시간 걸린다.
- 메모리는 실행 시간에 비례해 늘지 않도록 기록·화면 목록에 상한을 두었다 (실행 기록 파일은 디스크에 쌓인다).
